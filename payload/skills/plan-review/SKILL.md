# 高影响方案反例评审

- 对每条关键验收要求反问：哪些错误实现仍会让它通过？列出最可信的反例及最小可失败证据，优先覆盖真实入口、旧客户端、并发/重试和恢复路径。
- 检查危险窗口：失败发生在写入、提交、切换或清理的哪一刻；操作者如何确认当前状态并安全恢复；是否可能重复执行或丢失并发新内容。
- 区分文档存在、测试夹具、静态预演、真实宿主与最终用户环境证据。只在当前授权环境验证；不以批准、固定评审轮数或完整测试清单代替证据。
- 对小而可逆的编辑不过度流程化；输出具体反例、缺失证据与影响，不为了“反例齐全”扩大修改范围。
