# 请求与任务异常恢复

- 先定位故障层：用户取消或主机停止、进程启动、网络/传输、HTTP/API 限制、流协议、工具执行或业务断言。保留首次失败与可用的请求/运行标识；不要把工具报错、启动失败或未知结果归成业务失败。异常应向上传播，或在有上下文时包装并保留 `cause`、错误类型和阶段；不得静默吞掉或伪装成功。
- 只有当前错误证据支持可重试时才重试。认证、权限、无效请求、额度耗尽和业务断言失败不能靠重复请求修复。遵从 `Retry-After`，退避并设预算；无限重试必须是用户明确选择的可取消模式。
- 传输中断后，上游可能已处理请求。先查回结果或幂等键状态；对写操作、工具调用、部署和付款等有副作用的动作，不因超时而盲目重放。重试可能重复上游计算或计费。
- 遇到轮次/上下文上限时，依据真实错误码启用已授权的恢复路径。只压缩已闭合的历史，保留当前目标、未完成项、最近证据，以及每个工具调用与结果的完整配对；精确匹配检查点后续接。不能确认源前缀一致时，不复用旧摘要。
- 流式响应只有在协议声明的终态和必需字段完整时才算成功；HTTP 200 或 EOF 不等于成功。截断或格式错误的流不得作为完整结果转发，尤其不得执行部分工具调用。
- 并行任务异常后，先对账已完成、已写入、预期未完成及未知状态；只补差集，不能因 worker 退出就整批重跑。独立批处理逐项记录成功、失败与未知；任何失败都必须让最终汇总保持失败，不能被后续成功覆盖。未知副作用先只读查回；仍无法确定时保留未知并升级给用户。
- 任务因轮次上限、中断或代理退出而续接时，重读当前目标与进度，区分已完成、未验证、下一步和阻塞；继续同一授权任务，不重复已完成动作，也不把子任务结束当作总任务交付。
- 日志不得包含提示正文、认证头、API key、工具参数或摘要正文。不要把会话历史转发给配置之外的上游；摘要和检查点也可能含敏感信息，应限定本地权限与保留。
- 可选恢复网关只在用户选择安装并配置时使用。确认上游为预期的本机代理、绑定仅回环地址、检查端口冲突；不要自动改供应商/模型/密钥配置、启动后台服务或声称宿主已接线。历史摘要会发给同一上游模型并产生额外请求；先告知隐私与费用影响。
- 用户主动取消、停止会话或撤回授权时立即停止恢复尝试。保留已证实进度，标注未完成项；不得自行续跑已停止的会话。
