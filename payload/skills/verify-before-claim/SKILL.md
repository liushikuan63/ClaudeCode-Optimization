# 先验证，再下结论

## 执行

- 明确本次要证实的命题、当前目录/版本、实际入口及能判失败的标准。沿用已有授权；本技能不授予发布、停服务、修改生产或调用付费模型的权限。
- 旧报告仅作线索。使用当前配置、进程/端口归属、实际请求或当前产物，不用其他目录、旧构建或旧进程冒充现场。
- 要求与证据绑定同一最终代码、配置、产物和环境；最后一次可能影响结论的修改后，重跑受影响检查，不能拼接不同状态的全绿记录。
- 运行与改动直接相关的检查，保留命令、退出码和关键断言；负对照必须因目标断言而失败，不能把缺依赖、启动失败或无关超时当作有效红例。跳过与预期失败单独说明。
- 小改先做精准检查；影响多个层次时覆盖不同盲点，例如静态语法与真实装载、单测与真实调用。不要重复跑同一种检查假称独立复核。
- 回归覆盖受影响的其他路径。失败先定位具体层次，不靠重复重跑抹掉证据，也不无依据扩大修复范围。
- 偶发失败保留首次断言、代码字节、运行时、环境/cwd及并发或超时线索；复跑转绿不是根因修复，归因缺证据就保持未知，不套固定次数或一律串行的规则。

## 不同入口的最低证据

| 入口 | 应验证的事实 |
| --- | --- |
| 文本/配置 | 可解析；目标片段或字段正确；不再适用的旧片段确实移除；无关字段不变 |
| 命令 hook | 输入事件和输出 JSON 契约；正确事件、无关事件、坏输入和超时；脚本直测与宿主实际触发分开报告 |
| MCP | 配置位置正确且无重复；当前宿主列出工具；最小授权下实际调用成功，不能只看启动命令 |
| 服务/数据 | 当前实例与请求结果、必要负向对照；生产只读探针，不为验证写数据或重启 |
| UI | 实际加载与关键交互；控制台/网络；有视觉变化时截图，精确样式用 DOM 检查 |
| 构建/安装包 | 本轮重建后的最终产物启动和关键路径，不用源码开发态代替 |

## 汇报

分清“已写入”“静态/单测通过”“当前宿主已加载”“端到端通过”。仅报告实际执行的级别、覆盖和缺口；未拿到现场证据就写“尚未验证 + 原因”，不要写“应该已生效”。普通配置验证不用启动付费模型调用。
