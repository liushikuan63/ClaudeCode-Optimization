# 数据库变更与恢复

- 先核当前仓库的引擎/版本、迁移工具、已应用版本、目标 schema/table、数据量和并发读写；区分权威表、视图、缓存和派生副本。版本、规模或目标未明时只给静态方案，不宣称无锁或零停机。
- 写操作前用只读查询确认影响范围、边界样本和预期数量；参数使用绑定变量。批量 DELETE/UPDATE 不可因空筛选条件被静默放大到全表。
- 已应用且受校验和管理的迁移保持不变，以新迁移修正；只在确认尚未应用且归属明确时改当前文件。
- 结构/类型变更按兼容需要扩展、双兼容、稳定键有界回填、校验、切换、最后收缩。断点可恢复，重跑不覆盖回填期间的新写入、不重复生成数据；记录变更前后数量与核验条件。
- DDL 锁、默认值、索引和事务行为依引擎与版本，必须查目标版本资料；不可把 PostgreSQL、MySQL 或其他引擎的在线操作能力互套。
- 分开论证应用回退、schema 恢复、数据恢复；删除/有损转换不能仅靠 DOWN 文件证明可逆。生产执行、连接凭据、停服务及数据写入必须另有对应授权；准备变更不等于批准执行。
