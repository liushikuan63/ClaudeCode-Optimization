# 文本与传参安全

- 先读目标文件并确认编码、换行、实际解释器与改动归属；优先精确编辑，保留既有格式。整文件重写须有理由与可恢复基线。
- 文件内容和复杂多行脚本用写文件工具落盘，再交给对应解释器；不要把待写内容穿过多层 shell 的双引号、变量展开和命令替换。
- 有 exec 参数数组时按参数传递，不拼 shell 命令；Windows 含空格的可执行路径和脚本路径各自是一个参数。Git Bash 命令与展示给用户的 PowerShell 命令不要混用。
- 正则替换的目标字符串从真实文件提取，断言匹配次数；JS/Python 的替换文本含特殊替换符时用函数式替换，避免把美元符号或反斜杠解释成捕获组。
- 中文脚本按实际执行器选择编码：现代 Node/Python/PowerShell 7 通常可用 UTF-8；Windows PowerShell 5.1 的中文脚本须核实 BOM，cmd/bat 须核实代码页与 CRLF。不要批量盲转 GBK 或 BOM。
- Git Bash 向 Windows 原生程序传路径时检查 MSYS 路径转换；不要把 POSIX /tmp 直接当 Windows 路径，使用已知的绝对路径或解释器临时目录 API。
- 管道末端成功不代表前面的命令成功；取真实命令退出码，不把日志截断器的退出码当测试结果。

## 校验

按文件类型运行解析器或语法检查，例如 JSON 解析、node --check、bash -n 或项目现有检查；同时断言新内容存在、已淘汰旧内容不存在、替换次数和体积变化合理。需要字节证据时用程序检查目标字节；编辑工具成功本身已证明写入完成，不为机械回读重复读取整文件。

同一文件不并发写；修改分批可验证，检查覆盖本批所有变更。遇到守卫或权限拒绝先调整合法方案，不改名、换工具或改执行通道绕过。
