# SPA 启动分层排障

- 先保留首次失败的 URL、响应、控制台和网络现场，再做单变量诊断；不要先清缓存或反复重载抹掉症状。
- 文档导航返回 200 可能是 SPA fallback HTML，不代表 JavaScript chunk 或对应路由加载成功。检查响应 Content-Type、脚本请求、模块导入和实际应用状态。
- 按文档请求 → 静态资源/chunk → API → 应用路由与状态逐层定位。一次只注入或改变一个故障条件，并保留首次失败与后续重试的区别。
- 自验正常但用户仍旧版时，核对真实入口/重定向、HTML 与 fallback 缓存策略、Service Worker 和所载 bundle 身份；旧 hash 资源返回 200 不证明新版已生效。
- 必要时用已授权的隔离会话或冷环境对照已有缓存状态；先保留原现场，不默认清用户缓存、注入或复制真实凭据，也不因此直接改生产缓存策略。
