# 文档修改流程

- 先查项目现有文档、链接和代码事实源；沿用现有 Wiki/索引，不为小改动新建独立文档体系。代码实现和当前配置优先于可能过期的说明。
- 大批量或跨模块改写时才指定唯一事实源、更新范围和写作约定；并发写作按独立目录/章节分配唯一负责人，编辑者不重复已经完成的源码研究。
- 文档交付区分已证实现状、计划变化、待实测项和待授权动作。命令/路径按适用环境验证；避免把模板、历史版本或预期行为写成当前事实。
- 更新会影响的索引和引用；检查目标链接真实存在且语义仍匹配。若校验前置台账本身改变了输入，再运行受影响的门禁；不为“绿”降低验收标准。
