# 任务接续与状态对账

- 用户要求继续上次工作、从中断/上下文压缩/会话交接后接续，或复核先前“已完成”结论时使用。只做单项验证而不涉及任务接续时，优先用 `verify-before-claim`。
- 先恢复用户原始目标、明确约束、审批边界和验收条件，再读当前任务清单与进度。旧摘要、代理报告和队列状态只是线索，不是授权或完成证据；不要扩大范围，也不要追读无关会话或私人历史。
- 对照当前工作树、文件内容、改动归属、配置/安装副本及本轮真实测试结果，逐项检查所有声称已完成的验收条件。文件存在不证明已安装或加载；检查器改过须在最后一次修改后重跑；旧测试结果只证明当时那份代码和环境。内容哈希证明字节身份，不证明正确性或实际运行。
- 标记每项为“已验证、失败、未完成、未验证、不适用”，并附当前证据。区分已写未执行、验证器已改未复验、缺产物和提前报完成；只核对原始验收条件，不追加新门槛。
- 对安装、提交、发布、部署、付款、工具调用等不确定副作用，先只读查状态和对象标识；确认安全、幂等后才在原授权范围内补做。结果未知且不可安全判定时保留“未验证”，不要盲目重放。
- 审计后在原授权范围内继续尚未完成且可安全执行的工作，不因接续本身反复询问是否继续。仍需用户批准的动作、权限拒绝或无法判定的高影响副作用不得自行推进。
- 不自动创建或更新持久队列、检查点、记忆或会话文件；使用当前 Claude 会话已有的进度载体即可。独立代理的完成报告不是验证，核对其实际改动与结果后再接手。
- 最终简要报告已验证项、失败项、未完成/未验证项及下一步；仅当所有原始验收条件都有充分证据时才称交付完整。

遇到需要证明代码、配置、Hook/MCP 接线、运行或产物状态的单项断言时，继续遵循 [`verify-before-claim`](../verify-before-claim/SKILL.md)。
