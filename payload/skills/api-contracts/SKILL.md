# API 契约

- 先沿实际路由、schema/DTO、契约测试和消费者确认认证、错误封装、分页与字段语义。已有客户端行为是兼容边界；不因风格偏好擅自重命名、改返回包装或切版本。
- 区分新增与破坏性变化；评估字段缺省、null、类型、状态码、排序、页大小、租户边界和错误结构。请求参数不能自行决定可信租户或资源授权范围。
- Cursor 分页须有稳定排序和唯一兜底字段，说明筛选变化时行为；用跨页边界测试确认无遗漏、无重复。
- 重试写操作应界定幂等键的调用方/操作/请求内容范围，处理并发首次请求、同键异内容、业务提交与结果记录一致性、进程重启和键保留期。禁用前端按钮不构成服务端幂等保证。
- 流式接口分开验证传输结束、协议完整、业务/生成成功，以及透明代理时的内容一致；覆盖 UTF-8 跨块、行尾、多 data 行、截断、响应 ID 和工具参数分片。按接口契约判终态，EOF 不替代契约要求的完成事件。
- 超时分层核对 DNS/连接、响应头、空闲及流中断；客户端先断连并不足以排除代理或上游问题，不为保活伪造业务事件或改写响应身份。
- 沿项目锁定版本查依赖 API；用与变化对应的消费者、权限、非法值、分页和重复请求测试。真实请求未执行时，明确只做了静态或单元验证。
